# スタッフ専用ページ（本日のチラシ・お知らせ）の設定

`/staff` に、スタッフだけが入れる「本日のチラシ・お知らせ」の設定ページを実装済み。
コード側は完成しているが、使い始めるには Cloudflare ダッシュボードで
**パスワードの設定があと1つ**必要。

## 毎日のチラシ更新（/staff）

デザイン案「スタッフ投稿画面」の配色・レイアウト（左メニュー・カード・右の補助パネル・見え方の確認）に合わせた画面。

1. パスワードでログイン（ログイン状態は30日間保持）
2. 「写真を選ぶ・撮る」で今日のチラシを選ぶ（スマホならカメラで撮影も可）
   - JPEG・PNG・WebP・PDF、**最大4枚**（表・裏など）、1枚10MBまで
   - 大きな写真は、ブラウザ側で自動的に長辺2400px・JPEGに縮小してから送信（4800×6400の写真が約0.3MBに）
   - 並べ替え（◀▶）と取り消し（✕）ができる
3. 掲載する日（ふだんは「今日」のまま）と、何日間掲載するか（当日のみ／2日／3日／5日／1週間）を確認
4. タイトルは空欄なら「10月31日（土）本日のチラシ」と自動で付く。ひとことは任意
5. 「見え方を確認」で公開前の見え方を確認し、「アップロードして公開する」を押す

- 同じ日のチラシが既にあるときは、新しいチラシに**自動で置き換える**（チェックを外せば並べて掲載）
- 前日までに「明日の日付」で登録しておくと、その日の0時から自動で公開される
- 時刻（既定 0:00〜23:59）や外部リンクは「くわしい設定」から変更できる
- 「お知らせ・情報」も同じ画面で登録できる（タイトル必須）
- 右上の「いま公開中のチラシ」に、いま公開されているチラシが表示される。無いときは黄色の注意が出る
- 登録済みの一覧は 掲載中／掲載予定／掲載終了 のラベル付きで、削除もできる

## 社長ブログ・スタッフブログ・レシピ（/staff/posts）

デザイン案「スタッフ投稿画面」の項目（タイトル・カテゴリー・担当者名/店舗・本文・写真・写真の提供者・写真の説明・掲載可否の確認・動画URL・公開までの流れ）に対応。

- 左メニューの「社長ブログを書く」「スタッフブログを書く」「レシピを書く」から新規作成。「記事の一覧・確認」で状態別（下書き／確認待ち／公開中）・種類別に絞り込み
- 写真は最大6枚（スマホの大きな写真は自動で縮小）。1枚目が一覧の表紙。写真を載せるときは「掲載可否を確認しました」のチェックが必須
- レシピは「分量」「調理時間」「材料（1行1品）」「作り方（1行1手順・番号は自動）」＋ひとこと
- 動画URLは、YouTube なら記事の中に埋め込み表示、それ以外は「動画を見る」ボタン
- 「記事の見え方を確認」で公開前の見え方を確認できる
- 空行を入れると、本文が段落に分かれる

### 公開までの流れ（役割は2つ）

| 役割 | ログインに使うパスワード | できること |
|---|---|---|
| スタッフ | `STAFF_PASSWORD` | 下書きの作成・保存、管理者への確認依頼、今日のチラシの更新 |
| 管理者 | `ADMIN_PASSWORD` | 上に加えて、記事の公開・取り下げ・差し戻し・削除 |

1. スタッフが下書きを書き、「管理者へ確認を依頼」を押す（状態：確認待ち）
2. 管理者が内容を確認し、「公開する」を押す（一覧からワンクリックでも可）。直すところがあれば「下書きに差し戻す」（ひとこと付き）
3. 公開中の記事は、スタッフには編集できない（管理者だけが編集・取り下げできる）

- 確認依頼・公開に必要な項目（タイトル、本文またはレシピの材料・作り方、写真の掲載可否）が足りないときは、入力内容を下書きとして保存したうえで、足りない項目を案内する
- **`ADMIN_PASSWORD` を設定しないと**、`STAFF_PASSWORD` でログインした人がそのまま公開できる（確認の流れは使わない）。確認の流れを使うには、`STAFF_PASSWORD` と同じ手順で `ADMIN_PASSWORD`（スタッフとは別のパスワード）を Secret として追加する
- 未公開の記事は、ログイン中のスタッフだけが /blog/＜記事ID＞ でプレビューできる

### お客様側の表示

- 一覧：**/blog**（すべて／社長ブログ／スタッフブログ／レシピ の切り替え）。記事：/blog/＜記事ID＞
- ホームの「お知らせ・ブログ」欄の「社長・スタッフのブログ・レシピ」に、公開中の最新5件を表示（記事が無い間は、これまでのサンプル表示のまま）
- ホームのヘッダー・フッターにも「お店のたより」のリンクを追加

## 公開ページへの反映

- 掲載期間内のものだけがホームページに出る。**掲載終了の日時を過ぎると自動的に消える**（操作不要）
- ホームの「よく使うメニュー」直下に「本日のチラシ・お知らせ」ブロックが出る（チラシは最大2枚分のサムネイル）。掲載中のものが無ければブロック自体が出ない
- ホーム各所の「今日のチラシ」リンク（ヘッダー・ヒーロー・メニュー・今夜の献立・店舗一覧）は、掲載中のチラシがあれば **/flyer**（スマホで大きく見られるチラシ専用ページ。全ページを縦に並べて表示）に、無ければ従来どおり外部の `kimura-group48.jp/flyer.php` に飛ぶ
- /flyer は、掲載中のチラシが無ければ外部の既定ページに自動で転送される。画像・PDFが無くリンクURLだけのチラシは、そのリンクに転送される

## 必要な作業（Cloudflareダッシュボード側）

※記事の確認・公開の流れを使う場合は、手順3〜4と同じ要領で `ADMIN_PASSWORD` も Secret として追加してください（任意）。

1. [Cloudflareダッシュボード](https://dash.cloudflare.com) → **Workers & Pages** → `kimuraya-katamachi`
2. **Settings** → **Variables and Secrets** → **Add**
3. Type を **Secret**、Variable name を `STAFF_PASSWORD`、Value にスタッフ用のパスワードを入れて **Deploy**
4. `https://kimuraya-katamachi.co.jp/staff` を開き、そのパスワードでログインできれば完了

パスワードを変えると、ログイン中のスタッフは全員ログアウトになる（再ログインすればよい）。

## 仕組み

- 記事は KV の `article:<id>`（本文）と `articles:index`（一覧用の要約）に保存。写真は `file:<id>`
- 保存先：Cloudflare KV（`wrangler.jsonc` の `STAFF_KV`、namespace `kimuraya-katamachi-staff`）。作成済み
- 登録内容は `posts` キーに JSON、アップロードした画像/PDF は `file:<id>` キーに保存（1つの登録に最大4ファイル。以前の「1ファイル」形式のデータもそのまま読める）
- 配信：`/f/<id>`（`app/f/[id]/route.ts`）、チラシ専用ページ：`/flyer`（`app/flyer/page.tsx`）
- 認証：`STAFF_PASSWORD` と照合し、パスワードから導出したトークンを HttpOnly Cookie に保存（`app/lib/staff-auth.ts`）
- ローカル開発：`.dev.vars` に `STAFF_PASSWORD=任意` を書けば `npm run dev` でそのまま動く（KV はローカルの擬似ストレージ）
